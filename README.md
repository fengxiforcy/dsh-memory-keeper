# dsh-memory-keeper

> 压缩 + 记忆联动插件：**对会话日志压力做监测与维护**的自动记忆守夜人。

DeepSeek Harness（DSH）的上下文压缩会丢细节、会话日志只增不减会撑爆请求体。这个插件在**压缩之前先把值得记的事提炼进长期记忆**，并**持续监测会话日志的体积、在危险前提醒你换本子**。

## 为什么做它

1. **压缩丢知识**：DSH 到线压缩时只留摘要，被压掉的原文里往往藏着决定、承诺、踩坑记录。本插件在压缩前自动整理记忆，压缩后知识还在。
2. **会话日志无限增长**：DSH 的 `session.v4.jsonl.zstd` 只增不减、不轮转。日志涨到很大后，请求体可能被静默截断，会话永久损坏（自锁，只能重置）。本插件监测日志体积：>50MB 预警、压缩完成时顺带报体积，提醒在危险前开新对话。
3. **看不见的压缩**：后台压缩没有反馈，用户不知道压了多少、记忆写了几条。本插件把每一步都显式报在对话里。

## 核心功能

- **压力探针**：每个 agent 步测量上下文占用，写入压力日志（可选，默认只记一行/分钟）。
- **到线自动整理**：上下文达到阈值（默认 45%，按工作区可配）时，先让模型从「上次整理到现在」的对话里提炼记忆，分三层写入（core 正殿 / topics 分厅 / events 事件），再压缩。
- **强制整理后再压缩**：整理永远在压缩之前完成，原文存档到 `记忆/archive/`，不丢知识；整理真失败时跳过压缩（10 分钟冷却后重试，连续 3 次才放行）。
- **会话日志压力监测与维护**：每次压缩完成在对话里报告「当前账本 XX MB」；>50MB 给出换本子预警；压缩前把会话日志文件本身备份一份（保留最近 5 份，损坏时可回滚）。
- **关键事件即时捕获**：每轮对话用规则扫描「发布/上报/决定/承诺/配置变更/批准/删除」等关键词，命中就直接写一条事件记忆——不调模型、不等压缩，重要的事永不漏记。
- **定期整理**：每 N 轮（默认 5）在会话空闲时做一次只整理不压缩的轻量整理。
- **热加载**：改逻辑文件（logic.cjs）下一条事件即生效，不用重启 DSH；新代码解析失败自动回退旧版本。
- **可见性**：压缩完成在对话里报告：整理了几条、压掉多少、上下文变化、当前账本体积、候选/待办数量。

## 与市面插件的差异

| 类型 | 代表 | 做什么 | 本插件 |
|---|---|---|---|
| 记忆存储派 | dsh-memory-core / jipika / jacklika / ltm | 存记忆、agent 主动 recall | **不是存储层**：把记忆整理**挂在压缩流程上**，压缩前自动提炼 |
| 压缩派 | dsh-context / compaction-vcc / instant | 压缩上下文、控制预算 | **压缩前先整理记忆**，压缩与记忆联动 |
| **本插件** | — | — | **压缩 + 记忆联动 + 会话日志压力监测维护** |

## 安装

```jsonc
// profile package.json
{
  "dependencies": { "dsh-memory-keeper": "^0.1.0" },
  "dsh": {
    "profile": {
      "bundles": [ /* ... */, "dsh-memory-keeper" ]
    }
  }
}
```

装好后在 profile 目录执行安装（如 `npm install`），插件会在 DSH 启动时加载。

## 配置

配置文件默认在 `$DSH_HOME/memory-keeper/config.json`（也可用 `DSH_MEMORY_KEEPER_CONFIG` 指定），**热重读，改完不用重启**：

```jsonc
{
  "threshold": 0.45,                 // 触发整理+压缩的上下文阈值（按工作区可覆盖）
  "selfCompactWorkspaces": ["E:\\ws-a"], // 允许插件自己动手压缩的工作区白名单
  "selfCompactThresholds": { "E:\\ws-a": 0.45 },
  "selfCompactKeep": 4,              // 压缩后保留最近几条消息
  "notifyWorkspaces": ["E:\\ws-a"], // 哪些工作区在对话里显示提示
  "instantCapture": true,            // 关键事件即时捕获
  "groomEverySteps": 5,              // 每 N 轮做一次轻量整理
  "maxTokens": 8000                  // 记忆整理单次模型输出上限
}
```

工作区路径与 DSH 的 workspace 存储一致；默认目录跟着 `DSH_HOME`。

## 架构

- `index.js`：稳定壳——注册钩子、持有运行时状态（Map/Set）、按 mtime 热加载逻辑、错误回退。
- `logic.cjs`：可变逻辑——阈值判定、记忆提取、压缩动作、提示文案（CommonJS，便于热重载）。
- 状态（排队/水位/退避）在壳里，热加载不丢现场。

## 已知限制

- 压缩动作依赖 `session.append + surfaceOp`（第三方插件层拿不到 DSH 的 compaction 服务锁）；已在白名单工作区试运行稳定后再铺开。
- 记忆整理质量取决于模型；提取不完美时可手动用 `memory.mjs` 补。
- 版本对齐：在 DSH 0.2.2-rc.3 上验证。DSH 升级后建议先小范围验证。
